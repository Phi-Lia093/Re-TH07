# Bomb 实现对照（灵梦两种 Bomb）

> 来源：`FUN_00408710`（Bomb A）与 `FUN_004091b0`（Bomb B）。
>
> **位置正确性相关的全部数值已实测。**

---

## 1. 两个 Bomb 的参数对照

| 参数 | Bomb A（梦想封印） | Bomb B |
|------|-------------------|--------|
| 总时长 | **140 帧** | **300 帧** |
| 玩家缩放 | **200** | **360**（`0x168`） |
| 生成窗口 | 第 8–79 帧 | 第 **60–179** 帧 |
| 生成间隔 | **6 帧** | **16 帧** |
| 生成数量 | 12（index 0–11） | **8**（index 0–7） |
| 方向 | **8 等分，-π/2 起** | **随机** `rand()*2π - π` |
| 初速 | **15.0** | **8.0** |
| 减速 | **0.4/帧** | 见下 |
| 弹幕等级缩放 | 0.4（`0x3ecccccd`） | **0.22**（`0x3e6147ae`） |
| 额外状态 | — | `+0x23f4`/`+0x23f0` = **0.6** |

## 2. Bomb A 位置公式（已详述于 `docs/42`）

```lua
angle = index * (2*pi/8) - pi/2
if start_x >= 192 then angle = -angle_series end   -- 镜像
speed = 15.0, decel = 0.4 per frame

pos.x = cos(angle) * speed + start_x
pos.y = sin(angle) * speed + start_y
```

---

## 3. Bomb B 位置逻辑

```c
// 每个弹生成时
slot->active = 1;
slot->state  = 0;
slot->speed  = 8.0;                     // 0x41000000
slot->pos.x  = player->x;               // ← 玩家当前位置
slot->pos.y  = player->y;
slot->pos.z  = player->z;

// 方向完全随机
angle = rand_uniform() * 2π - π;        // [-π, π)
polar_to_xy(slot, angle, slot->speed);

// 绑定 4 个动画脚本
for (k = 0; k < 4; k++)
    anm_set_sprite_script(slot + k, 0x485 + k);

snd_request(0xd, 0);
```

### 3.1 与 Bomb A 的关键差异

| 方面 | Bomb A | Bomb B |
|------|--------|--------|
| 方向 | **固定 8 等分** | **纯随机** |
| 起始位置 | **释放瞬间固定** | **每弹生成时取玩家位置** |
| 覆盖形状 | 完美的 8 向对称 | 随机散布 |

> **重要**：Bomb A 的所有弹共享同一个 `start_x/y`（释放瞬间位置），
> 所以形成**规整的八方向星形**。
> Bomb B 每个弹单独记录玩家位置，形成**不规则散落**。

## 4. 8 个槽位的渲染（`FUN_00408e10`）

每个槽位包含 **4 个子精灵**，位置 = 槽位位置 + 各自的偏移：

```c
for (i = 0; i < 8; i++) {
    slot = &effect_slot[i * 0x1428];
    if (slot->active) {
        // 子精灵 0
        sub[0].pos = slot->pos + slot->offset[0];
        sub[0].pos += screen_offset;      // 加屏幕偏移
        anm_draw(sub[0]);

        // 子精灵 1
        sub[1].pos = slot->pos + slot->offset[1];
        sub[1].pos += screen_offset;
        anm_draw(sub[1]);

        // 子精灵 2, 3 同理
    }
}
```

### 4.1 子精灵偏移字段

| 子精灵 | AnmInstance 字节偏移 | 间隔 |
|-------|---------------------|------|
| 0 | **`+0x1B8`** | — |
| 1 | **`+0x404`** | **588** |
| 2 | **`+0x650`** | **588** |
| 3 | **`+0x89C`** | **588** |

**间隔 588 字节 = `0x24C`** —— 正是 AnmInstance 的大小。
所以 4 个子精灵是**连续的 4 个 AnmInstance**。

但整个槽位步长是 **`0x1428`（5160 字节）**，约等于 **8.78 个 AnmInstance**，
不是整数倍 —— 说明槽位结构比 4 个实例更大（含状态字段）。

### 4.2 位置计算（重制版照抄）

```lua
-- 每个子精灵
sub.pos.x = slot.pos.x + sub.offset.x + screen_offset.x
sub.pos.y = slot.pos.y + sub.offset.y + screen_offset.y
sub.pos.z = 0                                  -- 强制归零
```

> **注意**：绘制时 **z 坐标被强制设为 0**（`local_10[0xe2] = 0`）。
> 这是为了保证 Bomb 特效永远在最上层。

## 5. 屏幕偏移（`_DAT_0062f864`/`_DAT_0062f868`）

```c
pos.x = pos.x + _DAT_0062f864;
pos.y = pos.y + _DAT_0062f868;
pos.z = 0;
```

**所有 Bomb 特效绘制前都加这个偏移**。

这是**游戏区在窗口中的位置**（`32, 16`，见 `docs/14`）。

**重制版必须应用，否则整个 Bomb 特效会偏移 (32,16) 像素。**

## 6. 重制版对照清单

### 6.1 位置正确性

| 检查项 | Bomb A | Bomb B |
|--------|--------|--------|
| 起始位置 | **释放瞬间固定** | 每弹的生成时刻 |
| 角度来源 | 8 等分（含镜像） | `rand()*2π - π` |
| 初速 | 15.0 | 8.0 |
| 子精灵偏移 | 4 层，各 +0x93 间隔 | 同 |
| 屏幕偏移 | **(32, 16)** | 同 |
| z 强制归零 | 是 | 是 |

### 6.2 常见错误

1. **Bomb A 做成跟随玩家** → 星形形状破坏
2. **忘记镜像**（x ≥ 192 时反向）→ 左右不对称
3. **漏掉屏幕偏移 (32,16)** → 整体偏移
4. **子精灵 z 不归零** → 被背景遮挡
5. **Bomb B 也做成固定角度** → 失去了"随机散落"感
