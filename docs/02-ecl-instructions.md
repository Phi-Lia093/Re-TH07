## 1. 解释器主循环（`FUN_00410520`）

### 1.1 上下文结构（每个实例 0x4F48 字节，最多 480 个）

| 偏移 | 内容 |
|------|------|
| `+0x6e4` | **当前指令指针 (IP)** |
| `+0x6f0` | 当前指令的 `time`（唤醒时刻） |
| `+0x6fc..0x708` | 全局整数变量 10000–10003 |
| `+0x70c..0x728` | 全局浮点变量 10004–10011 |
| `+0x72c..0x738` | 全局整数变量 10012–10015 |
| `+0x2a7c` | **调用栈深度**（0..15，共 16 层） |
| `+0x8fc + depth*0x218` | **保存的调用帧**（0x218 字节/帧） |
| `+0x2b08` | 等待倒计时（`> 0` 时阻塞） |
| `+0x2b0c..0x2b14` | 位置 x, y, z |
| `+0x2e28` | 状态位：bit0-1 插值模式，bit2-4 缓动类型 |
| `+0x2e29 / 0x2e2a / 0x2e2b` | 各种标志位 |

### 1.2 调度逻辑

```c
while (local_c = ctx->ip, ctx->wait <= -1) {   // 无阻塞时可连跑
    ctx->ip = local_c + instr->size;            // 先前进
    if (!ctx->flag_2e2a_bit5) save_frame();     // 备份当前帧
    FUN_0040e530(&ctx->ip, sub_offset[ctx->stack_depth]);  // 压栈
    if (ctx->stack_depth < 15) ctx->stack_depth++;
    ctx->wait = -1;
}
```

**关键语义**：
- `wait` 为负数表示「可继续执行」，解释器在一个 tick 内连续执行多条指令
- 遇到需要等待的指令（如 `ins_4` 设置等待）后 `wait >= 0`，退出循环
- 子程序结束（`ins_41` = ret）弹栈并**重新进入循环**（`goto LAB_00410531`）

### 1.3 指令分派

```c
if (ctx->instr_time != *ip) goto LAB_0041678f;      // 时间未到 → 本帧不执行
if ((ip->rank_mask & rank_bit) == 0) goto caseD_7e; // 难度不符 → 跳过
iVar14 = (short)ip[1] - 1;                          // opcode - 1
switch (iVar14) { case 0: return -1; /* id == 0 → 停止 */ ... }
```

- **`case N` 处理 `opcode N+1`**
- **opcode 0 = 停止该子程序并返回 -1**（即 `ins_0`，数据中出现 86 次）
- `caseD_7e`（opcode 126 落点）= 跳过本指令直接前进
- 指令头的 `size`（`ip[1]` 的高 16 位所在 dword）决定前进量

### 1.4 时间轴（`time` 语义）

```
指令的 time 是「绝对帧号」。ctx->instr_time 记录当前唤醒帧。
*ip (指令的 time 字段) 与 ctx->instr_time 不等时 → 本帧不执行，直接返回。
```

配合 `FUN_0043958d`（`+= dt`，累计到 1 即帧 +1），
在低于 100% 速度时（`DAT_00575ac8 < 0.99`），游戏**不以帧为单位**推进，
而是用**累积的浮点时间**推进，保证慢速时逻辑仍然平滑。

> **重制提示**：原版逻辑严格以「帧」为单位，
> 时间轴用浮点累加器实现「慢速」。重制版应保留**固定 60Hz 逻辑帧**，
> 而把减速实现为「逻辑帧按比例跳过」（原版做法），而不是可变时间步长。

## 3. 栈与调用

| opcode | 名称 | 语义 |
|--------|------|------|
| `0` | `ins_0` | **停止**：`return -1`，销毁/结束本实例 |
| `1` | `ins_1` | 无操作（`break`，直接前进） |
| `2` | `ins_2` | **无条件跳转**到绝对偏移 `ip[3]`（`caseD_1` 的简化） |
| `3` | `ins_3` | **条件跳转**：`--counter; if (counter >= 1) jump` |
| `41` | `ins_41` | **`call`**：`ctx->instr_time = ip[3]; ip += ip[4]` |
| `42` | `ins_42` | **`ret`**：弹栈，恢复帧 |

### `caseD_1`（真实目标）
```c
ctx->instr_time = local_c[3];        // 设置唤醒时间
local_c += local_c[4];               // 相对跳转（注意是 dword 偏移 ×4）
```

### `caseD_28`（`ins_41` = call）
```c
local_8 = local_c[3];                 // 目标子程序号
ctx->ip = local_c + size;             // 先保存返回点
save_frame();                         // 压栈
FUN_0040e530(&ctx->ip, local_8 & 0xffff);  // IP = sub_offsets[target]
copy_globals(DAT_01347aa0, ctx+0x744, 8 dwords);  // 保存临时变量
depth++;                              // 最多 16 层
```

### `caseD_29`（`ins_42` = ret）
```c
depth--;
restore_globals();
restore_frame(depth);
loop();    // 立即继续执行
```

**栈深上限 16**，溢出时报 `"error : no Stack Ret\r\n"`。

## 4. 参数编码（已由数据验证）

### 4.1 指令头

```c
struct instr {
    int32  time;        // +0
    int16  id;          // +4  opcode
    int16  size;        // +6  总字节数
    int16  rank_mask;   // +8
    int16  param_mask;  // +10
    /* 参数区，从 +12 开始 */
};
```

### 4.3 参数槽位与掩码的**真实**关系（已用原始字节验证）

以 `ins_4` 为例，原始字节：
```
mask=0x0001  size=20  data = 1c 27 00 00 | 85 00 00 00
                            （低 4 字节） （高 4 字节）
      local_c[3] = 0x0000271c = 10012     ← 目标变量 ID
      local_c[4] = 0x00000085 = 133       ← 操作数
```

`mask = 0x0001` 表示 **bit0 = 槽位 3**、**bit1 = 槽位 4**：

| 掩码位 | 对应槽 | 若该位为 0 | 若该位为 1 |
|--------|--------|-----------|-----------|
| bit N | `local_c[N+3]` | 槽内是**立即数** | 槽内是**变量 ID**，需间接取值 |

也就是说：
```
param slot i  (i = 0,1,2,...)  <-->  local_c[3 + i]  <-->  param_mask bit i
```

**验证**：`ins_4` 的 `mask=0x1` 只置了 bit0（槽 3 = 目标 ID，本就不需要间接），
bit1（槽 4 = 操作数）为 0 → 立即数 133。与 `thecl` 导出的 `ins_4([10012], 133)` 完全吻合。

### 4.4 两种操作数

```c
// 读操作数 (int)：bit 为 0 → 立即数；为 1 → 变量间接
if ((param_mask >> i) & 1)  x = read_var(ip[3+i]);
else                        x = ip[3+i];

// 写目标 (int)：FUN_0040ec00 用同一个 param_mask 定位槽
int *dst = (param_mask >> i) & 1 ? missing /* 见下 */ : &var(ip[3+i]);
```

### 4.5 「固定参数」——掩码管不到的参数

有些指令的参数**不受掩码控制**，恒占槽位。典型：

| op | 字节数 | 掩码 | 结构 |
|----|--------|------|------|
| 2 | 8 | `0x0` | `[jump_target]` 无条件跳转，无需掩码 |
| 30/32/34 | 16 | `0x1` | `[a, b, jump_target, ?]` 条件跳转 |
| 19 | 12 | `0x3` | `[dst, a, b]` 三槽，bit0/bit1 都可用 |

以 `op 2` 原始字节为例：
```
mask=0x0  data = 12 00 00 00 | dc ff ff ff
      槽3 = 0x12 (18)   槽4 = 0xffffffdc (-36)
```

### 4.6 读变量的两个宏

```c
// int
if ((param_mask & BIT) == 0)  x = ip[slot];      // 立即数
else                          x = read_var();    // FUN_0040e5b0

// float
if ((param_mask & BIT) == 0)  x = (float)ip[slot];
else                          { f = read_var_f(ip[slot]); x = (float)f; }  // FUN_0040edf0
```

> **这就是 ECL「很烂」的根源**：`ins_4`（整数加）、`ins_5`（浮点加）
> 都是独立 opcode —— 每条算术运算都要一次解释器分派。
> 重制版 **必须** 改成 Lua 原生运算符（见 §6）。

## 5.1 参数布局报告（L2 证据）

`tools/check_params.py` 对每个在数据中出现的 opcode 输出：
实际字节数、出现过的 `param_mask`、以及反编译里识别到的掩码参数读取。

示例（节选）：
```
  op  bytes        masks          masked reads (bit: kind slot)
   4  [8]          0x1,0x3        b1:vari@4          <- dst 固定, 值为 op
   7  [12]         0x1            b1:vari@4, b2:vari@5
   9  [12]         0x1,0x3,0x5,0x7 b1:varf@4, b2:varf@5
  27  [32]         0x1..0xf3      b1..b7: vari/vaf@4..10
  30  [16]         0x1            b0:vari@3, b1:vari@4   <- 但实际 16 字节=4 槽
```

注意 `op 30`：掩码只到 `0x1`（2 位），但字节数是 16（4 槽），
说明第 3、4 槽（`target` 及保留）**不受掩码控制**。
这类「固定尾参」是正确还原参数格式的关键，必须在逐条确认时逐个标出。

## 6. 重制版抽象原则（Lua）

原版 ECL 的问题：**算术是 opcode**。重制版必须：

```lua
-- 原版: ins_4([10012], 1)              -- 全局整数 += 1
-- Lua:  g.int[12] = g.int[12] + 1

-- 原版: ins_5([10004], 0.5)            -- 全局浮点 += 0.5
-- Lua:  g.float[0] = g.float[0] + 0.5

-- 原版: ins_7([10012], 6, 1)           -- g[12] = rand()%6+1
-- Lua:  g.int[12] = rng.int(1, 6)

-- 原版: ins_3(0, Sub1_176, [10012])    -- 倒计数循环
-- Lua:  for i = n, 1, -1 do ... end
```

**原则**：
1. **只在引擎侧 `call native`**，脚本侧全部用 Lua 原生结构
2. 保留 `time` 语义，但改为协程：`wait(frames)` = `coroutine.yield(frames)`
3. 子程序调用 → Lua 函数调用（不再受 16 层栈限制）
4. 变量系统 → Lua table（`g.int[]` / `g.float[]` / 局部 `let`）
5. 保留**原始 opcode 与 offset 的映射**，便于逐条对照验证

## 7. 待办与验证策略（无运行时的情况下）

由于**无法运行游戏**，采用三层校验替代轨迹比对：

| 层 | 方法 | 能发现的问题 |
|----|------|-------------|
| L1 数据自洽 | 每条指令 `size` 精确落在子程序边界（已 100% 通过） | 容器层错误 |
| L2 参数自洽 | 反汇编推出的「槽数」与真实 `size-12` 完全一致 | 参数格式错误 |
| L3 语义自洽 | 反汇编出的 opcode 语义 → 转成 Lua → 重新「解释」8 个关卡，检查无非法访问、无负跳转越界 | 语义错误 |

**L3 是最后的防线**：把 19919 条真实指令全部「模拟执行」一遍，
任何一条读不存在的变量槽、跳到越界地址，都说明语义理解有误。
