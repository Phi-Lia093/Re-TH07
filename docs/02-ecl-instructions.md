## 0. ⚠️ 对参考页的重要更正

`ref/` 中 Wiki 页面（`User:Mddass/Touhou File Format Specification/ECL`）
的 TH07 章节**只列了 6 个 opcode**（nop/delete/jmp/loop/iset/fset），
而实际有 **161 个**。排查后发现该页面**可信度有限**，已发现的问题：

| 问题 | 详情 |
|------|------|
| 覆盖极低 | 161 个 opcode 只写了 6 个（约 4%） |
| `iset`/`fset` 描述含糊 | 只说"Sets var to a"，未说明这是**唯一**的写变量原语 |
| 无参数位掩码说明 | 完全没提 `param_mask` 的语义 |

**但在已覆盖的 6 条上，参考页是对的**，并纠正了我的两处错误：

| opcode | 我的错误结论 | 参考页 | 反汇编复核 |
|--------|-------------|--------|-----------|
| 4 `iset` | ~~`var += a`~~ | `var = a` | ✅ `*piVar10 = iVar14;` 是**赋值** |
| 5 `fset` | ~~`var += a`~~ | `var = a` | ✅ `*pfVar11 = local_37c;` 是**赋值** |

> 教训：不能只看「写回了哪个变量」，必须看**写回的表达式**。
> 这条纠正直接否定了我先前"ECL 只有 add opcode"的推断 ——
> 真相是：**赋值是基本原语，`++`/`--` 是独立 opcode，加减乘除各有 opcode**。

## 1. 解释器结构

| 项 | 值 |
|----|-----|
| 解释器函数 | `FUN_00410520` |
| 实例池 | 480 个，每槽 `0x4F48` 字节 |
| 调用栈 | **16 层**，每帧 `0x218` 字节 |
| 分派 | `iVar14 = (short)ip[1] - 1; switch(iVar14)` |
| 映射 | **opcode N (N≥1) → `case N-1`** |
| opcode 0 | 无对应 case（`iVar14 = -1`）→ 落到 `caseD_7e` = **跳过 = nop** |
| 无效 opcode | 同上，一律当 nop —— 与参考页一致 [参考] |

### 1.1 指令头

```c
struct instr {
    int32  time;        // +0
    int16  id;          // +4
    int16  size;        // +6   总字节数
    int16  rank_mask;   // +8
    int16  param_mask;  // +10
    /* 参数槽，从 +12 开始 */
};
```

### 1.2 参数槽 ↔ 掩码

```
param slot i  <-->  local_c[3 + i]  <-->  param_mask bit i
```

- `bit i == 0` → 槽里是**立即数**
- `bit i == 1` → 槽里是**变量 ID**，需间接取值

**已用原始字节验证**（`ins_4([10012], 133)`）：
```
mask=0x0001  data = 1c 27 00 00 | 85 00 00 00
 slot3 = 0x271c = 10012 (目标)   slot4 = 133 (值，bit1=0 → 立即数)
```

### 1.3 三个访问原语

```c
// 读变量 (int) —— 也用于读操作数
x = FUN_0040e5b0();                 // 按当前槽里的 ID 取值

// 读变量 (float)
f = FUN_0040edf0(ip[slot]);         // 显式传槽号

// 取变量地址（写入目标），参数 0 = 槽索引
int  *dst = FUN_0040ec00(param_mask, 0);
float *dst = FUN_0040f3c0(param_mask, 0);
```

### 1.4 控制流目标（`caseD_1`）

```c
ctx->instr_time = ip[3];      // t
ip = (int*)((byte*)ip + ip[4]);   // cp：相对【当前指令】的字节偏移
```

**已验证**：`ecldata1` 中 `ins_3` @`0x244`，`cp = -0x18` →
目标 `0x244 - 0x18 = 0x22c`，正是 `Sub1` 的 `+0xb0` 处，
与 `thecl` 生成的标签 `Sub1_176` **完全吻合** [数据]

### 2.2 `ins_27` — 插值器（运动系统的核心）

每个 ECL 实例有 **8 个插值器槽**，位于 `+0x770`，每槽 12 dwords：

```c
for (slot = 0; slot < 8; slot++) {
    if (slot.free || slot.id == ip[3]) {
        slot.dst   = ip[3];                    // 目标变量（固定，不受掩码控制）
        slot.cur   = ip[4];  slot.cur2  = ip[5];  slot.cur3  = ip[6];   // mask bit1..3
        slot.func  = PTR_FUN_0049f3ec[slot.cur2];   // 插值函数 = 表[类型]
        slot.t0..t3 = ip[7..10];               // mask bit4..7  (float)
        break;
    }
}
```

**插值函数表 `PTR_FUN_0049f3ec`（已从 PE 直接读出）**：

| 索引 | 函数 | 含义 |
|------|------|------|
| 0–6 | `0x0040fb30` | **线性插值**：`v = (b - a) * t + a` |
| 7 | `0x0040fb90` | **三次样条**（4 控制点 Hermite 形式） |

```c
// FUN_0040fb30 (线性)
*pfVar1 = (fVar3 - fVar2) * param_3 + fVar2;      // a + (b-a)*t

// FUN_0040fb90 (三次样条, 4 控制点)
*p = (t-1)*t*t*P3 + (1-t)*(1-t)*t*P2 + (3-2t)*t*t*P1 + (2t+1)*(t-1)*(t-1)*P0;
```

> 这是 TH07 **所有平滑运动**（敌人轨迹、弹幕、背景视差）的底层机制。
> 重制版应实现为 Lua 的 `interp.lerp()` / `interp.spline()` 原生函数。

### 2.3 三角函数命名推导（重要）

`ins_24`/`ins_25` 通过 **x87 栈**传参，反编译看不出谁是谁。
用真实脚本的**使用上下文**反推（`ecldata1` @`0x3a20`）：

```lua
ins_25(10004, 10033)   -- A = f(angle)
ins_21(10004, 10004, 160)  -- A *= 160
ins_24(10005, 10033)   -- B = g(angle)
ins_21(10005, 10005, 160)  -- B *= 160
ins_19(10004, 10004, 10018) -- selfX += A     (10018 = Self X)
ins_19(10005, 10005, 10019) -- selfY += B     (10019 = Self Y)
```

已知 `10018 = Self X`、`10019 = Self Y`（变量表 33/34 项与参考页吻合），
在「角度从 +X 轴起算」的约定下，X 增量必为 `cos`、Y 增量必为 `sin`：

```
ins_25 计算 A（加到 X）→ ins_25 = cos
ins_24 计算 B（加到 Y）→ ins_24 = sin
```

> ✅ **op 12–16 已复核为三操作数**：原始字节 `mask=0x3`、24 字节 = 12+3×4，
> 槽 3 = 目标、槽 4/5 = 两个操作数。先前的"`var = var + a`"猜测**已被数据否定**。

## 3. 控制流全景

| op | 名称 | 语义 |
|----|------|------|
| 1 | `delete` | `return -1`，实例销毁 |
| 2 | `jmp` | 无条件跳转 |
| 3 | `loop` | 倒计数跳转（**不是** `while(var)`） |
| 41 | `call` | 调用子程序，压栈，**深度上限 16** |
| 42 | `ret` | 弹栈返回 |
| 126 | （落点） | 跳过本指令 |

`call` 的细节：
```c
target = ip[3];                      // 子程序号
ctx->ip = ip + size;                 // 返回点
save_frame();                        // 保存 0x218 字节到 +0x8fc + depth*0x218
ip = sub_offsets[target & 0xffff];
copy_globals(0x01347aa0 → +0x744, 8 dwords);   // 保存 8 个临时变量
depth++;
```

## 4. 重制版 Lua 抽象

原版把「赋值/自增/加减乘除」全做成独立 opcode，**这是必须消除的**。

```lua
-- 原版 opcode 序列                          -- 重制版 Lua
-- ins_4([10012], 133)   iset               g.i[12] = 133
-- ins_17([10015])       iinc               g.i[15] = g.i[15] + 1
-- ins_19([10004], a, b) fadd               g.f[0] = a + b
-- ins_21([10005], a, b) fmul               g.f[1] = a * b
-- ins_3(0, Loop, [10012]) loop             for i = n, 1, -1 do ... end
-- ins_6([10012], 6)     irnd               g.i[12] = rng.int(6)
```

**规则**：
1. 脚本层**只用 Lua 原生运算符**，不再有算术 opcode
2. 引擎侧只暴露 `call native`：`wait`、`spawn_bullet`、`set_pos`、`play_se`…
3. `time` → 协程：`wait(frames)` = `coroutine.yield(frames)`
4. 子程序 → Lua 函数（摆脱 16 层栈限制）
5. **保留 opcode ↔ Lua 行映射表**，便于逐条审计

## 9. 复核方法（无运行时）

1. 反编译里读**写回表达式**（不看变量名，只看 `*piVar10 = <expr>`）
2. 用 `tools/extract_opcodes.py --opcode N` 看原始 case 体
3. 用真实字节 `tools/check_params.py` 核对参数槽数
4. 与参考页比对，**冲突处以反汇编为准并记录**
5. 静态表用 `tools/pe_tables.py` 直接从 PE 读取，不依赖 Ghidra 识别
