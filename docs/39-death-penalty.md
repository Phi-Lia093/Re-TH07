## 3. 分数惩罚（复活时结算）

```c
if (+0x16a38 != +0x16a30) {
    if (score - stage_base < +0x16a2c)
        score = stage_base;              // 分数不低于关卡基准
    else
        score -= +0x16a2c;               // ← 扣除惩罚量
}
```

### 3.1 `+0x16a2c` 是惩罚量

它由 `FUN_00408610` 计算（见 `docs/32` 的 `bullet_rank_scale`）：

```c
// 难度越高，惩罚越轻
switch (difficulty) {
case 2: value /= 2; break;
case 3: value /= 4; break;
case 4/5: value /= 3; break;
}
value /= stage_max;
value -= value % 10;             // 取整到 10
+0x16a2c = max(value, param_2 / stage_max);
```

**难度越高，分数损失的比例越小** —— 这是 TH 系列的设计。

## 4. 樱点损失

`.sht` 中有 `cherry_loss_on_die = 0.5`（**死亡损失 50% 樱点**）。

`FUN_0042f526(200)` 处理 `+0x9640` / `+0x9634`：

```c
void FUN_0042f526(obj, amount)
{
    obj->counter -= amount;              // +0x9640
    while (obj->counter < 0) {
        obj->units -= 1;                 // +0x9634
        obj->counter += 100;             // 以 100 为单位
    }
    if (obj->units < obj->floor)         // +0x963c 是下限
        obj->units = obj->floor;
}
```

**以 100 为单位的计数系统**，每次死亡扣 200 = 2 个单位。

## 5. 完整死亡时间线

```
帧 0     : 被击中（未按 Bomb）→ 进入死亡状态
           ├─ 隐藏玩家精灵
           ├─ 扣除 200 单位（樱点/分数）
           ├─ Bomb 数 +6（上限 sht.bombs）
           └─ 开始 999 帧计时

帧 0-998 : 死亡动画 + 原地复活准备
           （期间 +0x16a20 = 1，玩家无碰撞判定）

帧 999   : 复活
           ├─ 分数 -= 惩罚量（由难度决定）
           ├─ 分数不低于关卡基准
           └─ 恢复玩家精灵与判定
```

## 6. 重制版照抄要点

### 6.1 必须精确复刻

| 参数 | 值 | 后果 |
|------|-----|------|
| 死亡持续 | **999 帧** | 死亡节奏 |
| Bomb 补偿 | **+6**（上限 sht.bombs） | Bomb 数量 |
| 樱点扣除 | **200 单位**（= 2 × 100） | 樱点曲线 |
| 分数惩罚 | `难度系数 / 关卡基准`，取整到 10 | 分数曲线 |
| 分数下限 | 关卡基准 | 防负分 |
| Bomb 键免疫 | `input & 2` | 死亡判定 |

### 6.2 容易做错的点

1. **Bomb 期间不会死亡** —— 判定在 `input & 2` 为真时跳过
2. **分数有下限**（关卡基准），不是归零
3. **惩罚量取整到 10** —— 不是精确值
4. **樱点以 100 为单位** —— 不是百分比直接计算
