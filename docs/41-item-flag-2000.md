# 道具标志 `0x2000` 调查结果（未完全解出）

## 1. 已知的确定事实

### 1.1 `0x2000` 的赋值位置

在 `FUN_004182d0`（敌人掉落处理）中：

```c
if (*(int *)(param_2 + 0x10) == 0) {
    local_18 = 0x2000;
}
else if (*(int *)(param_2 + 0x10) == 1) {
    if (difficulty == 3)          // Lunatic
        local_18 = 0x2000;
    else
        local_18 = 0;
}
else {
    local_18 = 0;
}
FUN_00424d20(&local_dc);          // ← 传入整个结构
```

### 1.2 触发条件

| `param_2 + 0x10` | 难度 | `local_18` |
|-----------------|------|-----------|
| **0** | 任意 | **0x2000** |
| 1 | **Lunatic (3)** | **0x2000** |
| 1 | 其他 | 0 |
| 2 | 任意 | 0 |

**`param_2 + 0x10` 是「敌人类别」**（0/1/2 三类）。

### 1.3 已知的位含义

在**对象通用标志**（AnmInstance 的 `+0x1c0`）中，
**第 13 位（`0x2000`）= 「已停止」**（见 `docs/16`）。

但这与道具的 `local_18` **不是同一个字段** —— 需要区分。

## 2. 未确认的部分

### 2.1 结构布局对不上

`FUN_004182d0` 中的结构以 `local_dc` 为基址，
按声明顺序推算 `local_18` 在 `+0x24`。

但 `FUN_00423730`（`item_spawn_ring`）读取的是：

```
param_2 + 0xbc   (ushort 标志)
param_2 + 0xbe   (short)
param_2 + 0xc0   (ushort)
```

**偏移完全对不上**，说明：
- `local_dc` 结构远大于 `0x2c`
- 或 `item_spawn_ring` 接收的是**另一份复制后的数据结构**

**这一点我无法在不完整追踪的情况下确定。**

### 2.2 可能的作用（**纯推测，勿采信**）

| 猜测 | 依据 | 可信度 |
|------|------|--------|
| 标记「特殊掉落」 | 只在特定敌人类别/难度出现 | 低 |
| 控制是否播放音效 | 与 `+0x62 & 0x200` 的检查相邻 | 低 |
| 影响道具散布方式 | 与行列布局逻辑相邻 | 低 |

**以上都不足以下结论。**

## 3. 重制版的建议

### 3.1 可以确定照抄的

```c
// 掉落时的标志设置
if (enemy_class == 0)       flag = 0x2000;
else if (enemy_class == 1 && difficulty == 3) flag = 0x2000;
else                        flag = 0;
```

**照抄这个条件判断**，即使不知道标志的具体效果。

### 3.2 需要验证的

如果重制版实现后发现：
- 某种敌人的掉落物行为与原作不符
- 或道具的吸附/消失速度不同

**再回来深挖这个标志**。

### 3.3 不影响的部分

这个标志**不影响**：
- 掉落数量（已确证：4/2 按难度）
- 掉落角度（已确证：π/6 或 π/2）
- 掉落速度（已确证：1.1/0.7/0.85 倍）
- 道具上限（已确证：1024）

**核心掉落机制已经完整**，这个标志只是外围修饰。
