## 1. stage ↔ ecldata 映射（已证实）

早期我按「文件名顺序」假定 `ecldataN` 对应 Stage N，但一直标记为**待验证**。
现在有三条独立证据共同确认它是对的：

### 证据 A：`th07.exe` 中的字符串表顺序

```
data/ecldata8.ecl   @0x970ac
data/ecldata7.ecl   @0x970c0
...
data/ecldata1.ecl   @0x97138     <- 严格倒序

data/stage8.std     @0x97b94
data/stage7.std     @0x97bb4
...
data/stage1.std     @0x97c04     <- 同样倒序，与上面一一对应

data/stg8bg / stg7bg / ... / stg1bg   <- 背景表，顺序一致
```

三张表**顺序完全平行**，说明代码里用同一个 stage 索引同时访问
`ecldata`、`stage.std`、`stgNbg`。

### 证据 B：`.std` 中的 BGM 引用严格递增

| 文件 | BGM 引用 | 关卡名 |
|------|---------|--------|
| stage1.std | `th07_02.mid`, `th07_03.mid` | Deep Mountain |
| stage2.std | `th07_04.mid`, `th07_05.mid` | — |
| stage3.std | `th07_06.mid`, `th07_07.mid` | — |
| stage4.std | `th07_08.mid`, `th07_09.mid` | — |
| stage5.std | `th07_10.mid`, `th07_11.mid` | — |
| stage6.std | `th07_12.mid`, `th07_13.mid` | — |
| stage7.std | `th07_16.mid`, `th07_17.mid` | Chinese Tea (Extra) |
| stage8.std | `th07_18.mid`, `th07_19.mid` | Chinese Tea (Phantasm) |

编号不重叠且递增，说明 `stageN` 就是第 N 关，不存在重排。

### 证据 C：`.std` 文件大小与关卡复杂度相符

`stage6.std` 只有 3144 字节（最短），`stage7/8.std` 完全相同（5744 字节，
共用同一套背景与地形，只在 BGM 和 ECL 上不同）——
这与 Extra/Phantasm 共用地图、内容不同的设计吻合。

### 结论

```
stage N  <-->  ecldataN.ecl  <-->  stageN.std  <-->  stgNbg.anm
          (N = 1..6 普通关, 7 = Extra, 8 = Phantasm)
```

## 2. `.std` 文件格式（部分逆向）

### 2.1 头部（已确认）

```c
struct std_header {
    uint16  unknown0;      // 见下表，疑为某种计数
    uint16  unknown1;      // 同上
    uint32  offset_a;      // 区段 A 的文件偏移
    uint32  offset_b;      // 区段 B 的文件偏移
};
```

实测（8 个文件）：

| 文件 | u16[0] | u16[1] | off_a | off_b | 文件大小 |
|------|--------|--------|-------|-------|---------|
| stage1 | 2 | 19 | 1772 | 2732 | 3552 |
| stage2 | 8 | 35 | 2436 | 3668 | 4388 |
| stage3 | 5 | 5 | 1488 | 2976 | 3836 |
| stage4 | 4 | 10 | 1592 | 4120 | 5920 |
| stage5 | 8 | 29 | 2268 | 4876 | 5676 |
| stage6 | 2 | 4 | 1352 | 1944 | 3144 |
| stage7 | 8 | 30 | 2296 | 4904 | 5744 |
| stage8 | 8 | 30 | 2296 | 4904 | 5744 |

`off_a` 与 `off_b` 的差值并不恒定（stage1: 960，stage2: 1232，stage3: 1488，
stage4: 2528，stage5: 2608，stage6: 592，stage7/8: 2608），
`文件大小 - off_b` 也各异（820、720、860、1800、800、1200、840、840）。
**区段长度规律未找到，待解。**

### 2.2 字符串区

关卡名以 CP932 编码存放，前缀为 `` ` ``（0x81 0x60 编码后的可见形式）：

```
@0x1b: "` Pseudo Winter"      (stage1)
@0x9d: "` Deep Mountain"      (stage1)
```

BGM 引用为 ASCII：`bgm/th07_02.mid`。

### 2.3 待解

已尝试但**未成功**的假设（记录下来避免重复走）：

| 假设 | 结果 |
|------|------|
| 区段长度 = `u16[1]` × 固定记录大小 | ✗ 各关比值差异极大（20.57 ~ 297.60） |
| 区段长度与 `u16[0]` 相关 | ✗ 同样无规律 |

结论：`.std` 内的数据不是简单的定长记录数组，
可能是变长记录或含二级偏移表。**需要单独一轮逆向**。

- [ ] `u16[0]` / `u16[1]` 的含义
- [ ] `off_a`、`off_b` 两个区段的结构
- [ ] 区段中是否有对象放置表、弹幕发生器坐标
- [ ] 与 ECL 中 `ins_94`（特效）等的关联

> **重制影响**：`.std` 若不解析，关卡背景与中继点无法还原。
> 但它属于渲染/关卡层，优先级低于 ECL 语义与 `.sht`，可放到 Phase 4。
