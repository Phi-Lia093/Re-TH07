# 慢动作系统（精读）

> 来源：`slowmo_enter`（`FUN_00418eb0`）与 `slowmo_exit`（`FUN_00418fc0`）。

---

## 1. 机制

```c
void slowmo_enter(ctx, params)
{
    // 1. 设置全局时间缩放
    g_slow_factor = 1.0f / (float)params->divisor;

    // 2. 使所有活动对象的速度按同一比例缩放
    for (i = 0; i < 0x400; i++) {
        obj = &objects[i];                     // 步长 0xd68
        if (obj->state != 0) {
            obj->vel.x *= g_slow_factor;
            obj->vel.y *= g_slow_factor;
            obj->vel.z *= g_slow_factor;

            // 3. 记录原精灵索引，切换到慢放图像
            obj->sprite_saved = obj->sprite;
            if (obj->sprite in 0x260..0x26f)
                anm_bind_sprite(obj, 0x26f);
        }
    }
}

void slowmo_exit(ctx, params)
{
    // 恢复速度
    f = 1.0f / g_slow_factor;
    for (i = 0; i < 0x400; i++) {
        obj = &objects[i];
        if (obj->state != 0) {
            obj->vel.x *= f;
            obj->vel.y *= f;
            obj->vel.z *= f;

            // 恢复原精灵
            if (obj->sprite in 0x260..0x26f)
                anm_bind_sprite(obj, obj->sprite_saved);
        }
    }
}
```

---

## 2. 关键设计

### 2.1 速度就地缩放

慢放**不是**把 `g_slow_factor` 应用到所有速度计算处，
而是**直接乘到每个对象的速度上**。

这意味着：

| 优点 | 缺点 |
|------|------|
| 不需要每处乘法检查 | 进入/退出必须精确配对 |
| 物理计算保持简单 | 中途生成的对象不受影响 |

> **重要**：慢放期间**新生成的对象不会自动变慢** ——
> 除非它的速度计算也乘了 `g_slow_factor`。

### 2.1.1 一个真实的正确性风险（**未解决**）

`g_slow_factor` 在整个二进制中出现在 **106 处**，包括：

| 位置 | 用途 |
|------|------|
| 粒子下落 | `y -= g_slow_factor * 0.5` |
| 子弹物理 | `vel += acc * g_slow_factor` |
| 玩家移动 | `dx * g_slow_factor` |
| ANM/CAM 插值 | 时间推进 |

而 `slowmo_enter` **另外**又把对象速度乘了一次 `g_slow_factor`。

**这意味着子弹速度可能被缩放两次**：

```
v' = (v * slow) + (acc * slow) * slow     ← 若两处都生效
```

**两种可能**：
- (a) 速度缩放只对**不由 g_slow_factor 驱动**的对象有效（选择性）
- (b) 确实双重生效，但因为是视觉效果，原作者没在意

**这一点无法从静态代码确定**，需要动态验证（比较慢放前后的实际位移）。
重制版在实现慢放前**必须先确认**，否则慢放会变成"慢的平方"。

### 2.2 精灵替换

```
原精灵索引 0x260..0x26F  →  替换为 0x26F
```

慢放时某些对象会**换成慢放专用图像**（可能是拖影或特殊视觉效果）。

退出时从 `sprite_saved` 恢复。

### 2.3 触发条件

两个函数都**没有直接调用者**，通过函数表挂接。
`params->divisor`（`+0x10`）决定慢放倍率。

从 TH 系列惯例，触发场景通常是：
- Boss 被击破
- 特定符卡释放
- 关卡结束时

> **标注**：具体触发点**未确认**，需要追踪函数表的填充位置。

## 3. 重制版照抄要点

### 3.1 必须保留

| 特性 | 原因 |
|------|------|
| 速度就地缩放 | 否则进入/退出不匹配会累积误差 |
| 精灵 0x260-0x26F 替换 | 慢放的视觉表现 |
| `g_slow_factor = 1/divisor` | 倍率语义 |
| 恢复用倒数而非保存原值 | 数值精度（见下） |

### 3.2 一个数值精度隐患

`slowmo_exit` 用 `1.0 / g_slow_factor` 恢复，而不是保存原始速度。

若 `g_slow_factor` 不是精确可逆的值（如 1/3），
反复进出会产生**浮点漂移**。

**建议重制版改为保存原始速度**，而不是乘倒数。

---

## 4. 与其他系统的影响

`g_slow_factor` 被以下系统读取：

| 系统 | 用途 |
|------|------|
| `player_update_input` | 移动速度 |
| 摄像机 VM | 插值推进 |
| ANM 解释器 | 动画速度 |
| 粒子系统 | 下落速度 |
| 子弹物理 | 速度积分 |

**修改 `g_slow_factor` 会让整个游戏同步变慢**，
这正是慢放效果的来源 —— 但也是它必须成对调用的原因。
